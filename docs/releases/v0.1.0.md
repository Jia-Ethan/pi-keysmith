# v0.1.0

First public candidate of `pi-keysmith`.

## Highlights

- Zero-runtime-dependency single-file Python CLI that deploys the bundled or a
  custom Markdown instruction as the pi global `SYSTEM.md`
  (`~/.pi/agent/SYSTEM.md`), which pi auto-discovers and uses to replace its
  default system prompt.
- No pi configuration file is mutated and pi has no hooks to isolate;
  `APPEND_SYSTEM.md` and `AGENTS.md` are left untouched and continue to stack
  on top as pi's own loader dictates.
- Bundled general engineering-assistant system prompt, embedded byte-for-byte
  in the script and mirrored as `examples/system-prompt.md`. Its SHA-256 is
  recomputed and displayed on deploy/status/dry-run.
- Manifest-based layered uninstall, durable transaction journal with immutable
  intent and before-state snapshots, explicit `--recover` for interrupted
  deploy/uninstall, read-only `--status`, preview-only `--dry-run`, and the
  `--yes` confirmation gate.
- Bilingual CLI output via `--lang auto|zh-CN|en`.
- POSIX atomic no-replace rename, file/directory `fsync`, no-follow regular
  file enforcement, `0600`/`0700` private journals. Windows fresh deployment
  open under `EXPLICIT_BETA` with a prominent CLI warning.
- `scripts/build_release.py` for deterministic candidate/formal release assets
  with tag/commit binding and `SHA256SUMS`.

## Verification

Run the local checks before treating any checkout as a candidate:

```bash
python3 -m py_compile pi-keysmith.py scripts/build_release.py
python3 -m pytest -p no:cacheprovider -q tests
python3 -m ruff check pi-keysmith.py tests scripts
```

Candidate assets require `--source-commit`; formal assets require
`refs/tags/<tag>` to point at HEAD:

```bash
RELEASE_TAG="v$(tr -d '\r\n' < VERSION)"
SOURCE_COMMIT="$(git rev-parse --verify 'HEAD^{commit}')"
python3 scripts/build_release.py "$RELEASE_TAG" --source-commit "$SOURCE_COMMIT" --output-dir dist-candidate
(cd dist-candidate && shasum -a 256 -c SHA256SUMS)
```

## Known limitations

- Single-file CLI; no `pip install` or automatic updater.
- Windows fresh deployment is `EXPLICIT_BETA` and is not a formal support claim.
- Python 3.9 is compatibility-test only; Python 3.10–3.14 is recommended.
- `main` / `Unreleased` is development state, not a formal Release.
- Backups and uninstall archives are not automatically cleaned.
